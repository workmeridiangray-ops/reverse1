# Scope checklist (source: "17 Manufacturing ERP & Production Planning SaaS – Full Scope")

Legend: ✅ built and verified by an automated test or the browser acceptance run · 🟡 built but simplified / partly verified · ❌ not built in this release · 🔌 needs an external account/credential to verify

| § | Area | Status | Evidence / limitation |
|---|---|---|---|
| 2 | Public site: home, product, solutions, pricing (live from plan versions), add-ons, demo, contact, help, updates, policy pages | ✅ | e2e: every page 200; lead forms store + email. Policy text is **draft — needs legal approval**. Trial = sign-up. |
| 2 | Sign up, verify email, sign in, 2FA (TOTP), recovery, invitations, workspace switch, access denied, suspended/expired session, profile, active sessions, notification prefs | ✅ | `tests/platform.test.ts` (lockout, single-use tokens, reset signs out all devices, invitation revoked/expired/used/wrong user); e2e. 2FA enrolment is by secret entry (no QR image). SSO / extra languages: not built (optional per scope). |
| 3 | Onboarding checklist, plan selection, checkout, usage, upgrade (prorated), failed payment + 7-day grace, cancel at period end, invoices keep plan version | ✅🔌 | Tests + e2e use the **sandbox provider** with the same signed-callback path. Razorpay Orders/Checkout/webhook code is written but **not exercised against Razorpay** (no keys). Downgrade is explained (applies at renewal; blocked while usage exceeds limits). Auto-debit recurring mandates not built. Export-and-closure: CSV exports only, no closure wizard. |
| 4 | Roles & permissions, invitations, deactivation with session revocation, audit trail, support-access approval | 🟡 | 11 internal + 2 portal roles, fixed matrix (role *editor* not built). **Plant-level access is enforced in the database** (restrictive RLS; tested). Support-access requests/approvals are recorded and audited, but there is no support "enter workspace" view yet. |
| 5 | Plants, locations, work centres, machines, shift calendar, items (make/buy/subcontract), units + approved conversions, alternates, customers, suppliers, item revisions, documents | ✅ | UI + tests. Master changes don't alter released jobs (snapshots). Warehouse = location list (no bin hierarchy). |
| 6 | Multi-level BOM, yield/scrap, routings with setup/run, versions, effective dates, cycle detection, ECR approval listing affected jobs, substitutions | ✅ | DB trigger + domain tests; chain test proves snapshot unaffected by ECO and frozen released BOM. Obsolete-component handling is by obsoleting the old version. |
| 7 | Quotation (estimate vs actual separate), customer order, lines, forecast netting, promise date, cancellation and **amendment** with effects, shortage preview, MTS reservation | ✅ | Amendment tested. Separate enquiry screen not built (quotation is the entry point). |
| 8 | MRP: deterministic, lead times on shift calendar, lot sizes, open supply, explanations, snapshot, deliberate release, stale-demand guard | ✅ | Domain + integration tests. Infinite capacity is stated on screen. Expedite/defer messages: past-due release date flagged only. |
| 9 | Load view, dispatch list, manual reschedule with dependency check + history + notification | 🟡 | No machine allocation board / capacity calendar grid. |
| 10 | Purchase request, RFQ, quote comparison, award → draft PO, PO with maker-checker, partial receipts, over-receipt block, subcontract reconciliation, supplier portal | ✅ | Tested end to end. Invoice reference captured on receipt only (no AP matching). |
| 11 | Immutable ledger, reversals, quarantine rules, batches, serials, transfer, adjustment with reason, opening stock, genealogy forward/backward, recall | ✅ | Concurrency and immutability tested on real Postgres. Code 39 labels + scan-to-open, blind count sheets built. Putaway/bin hierarchy not built. |
| 12 | Work orders: snapshot on release, material issue (over-issue guard), operation sequence start/pause/finish with time, output/scrap ceilings, rework, supervisor correction, downtime | ✅ | Chain test + e2e. Shared-terminal mode = individual sign-in (no PIN switch). |
| 13 | Inspections (incoming/in-process/final), measured limits, NCR dispositions (rework/return/concession/scrap), quarantine control, recall trace | ✅ | Chain test. Inspection plans (one characteristic with limits per item/type) built; multi-characteristic checklists not built. |
| 14 | Job cost (material/labour/overhead), standard vs actual variance, scrap cost, corrections in open period, period close, CSV accounting export | 🟡 | Worked example in `docs/costing.md` + unit test. WIP / FG / raw-material valuation shown; cost-model/standard-cost *versions* not built. |
| 15 | Availability, shipment from released batches, serial shipping, delivery confirmation (staff and customer portal), returns inspected before restock, customer/supplier portals, maintenance register + downtime | ✅ | Chain test + e2e (portal isolation). |
| 16 | Dashboards (shortages, adherence, yield/scrap, supplier delivery, late jobs), CSV import with preview/row errors (items, BOM, stock), audit, exports | 🟡 | Job margin report and period-review workflow limited to costing page. Saved views, bulk actions and quick-preview drawers: not built. |
| 17 | Super admin: overview, businesses, trials, plans/versions, invoices/payments/reconciliation refs, refunds (record), coupons, suspension, support queue, jobs/webhooks retry, audit, staff, announcements | 🟡 | Incidents, storage/deletion-failure screens, entitlement editor, credits not built. Provider-side refund not automated. |
| 16b | Data export (7 CSV kinds) and closure request (owner) | ✅ | Closure is a request; platform admin confirms (no automatic deletion). |
| 18 | Provider config, webhook logs, failed jobs/retry, import preview + row errors, backup/restore | 🟡 | Providers configured by environment, no in-app credential screen/field mapping. |
| 20 | Isolation, idempotency, bounded retries, upload checks, security headers, backup/restore exercise | ✅🟡 | RLS + composite FKs proven by tests/e2e (incl. guessed ids, file ids). **No antivirus scanning** (extension + signature checks only). No load/performance test was run, so BOM-depth/concurrency targets are unverified. |
